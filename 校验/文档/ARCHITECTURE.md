# 校验/ 领域驱动洋葱六边形架构设计说明书

## 一、模块定位与战略使命

`校验/` 是整个足球倍率推演系统的**法定质量与架构守门人（Quality & Consistency Gatekeeper）**。
它的核心使命有两个：
1. **彻底阻断大模型说谎与偷懒**：对球探网落盘快照 `data/YYYY-MM-DD/{matchId}.json` 进行 6 大黄金维度的物理穿透扫描，只要核心数据缺失直接以 `exit 1` 物理熔断进程，绝不给大模型留任何脑补和伪造盘赔的空间；
2. **平滑弱化并未来淘汰 `scripts/`**：收拢原 `scripts/check_consistency.py` 的全库一致性与图谱健康巡检职能，将 `scripts/` 降级为兼容垫片，实现系统向纯粹乐高架构演进。

## 二、10/10 纯 DDD 洋葱六边形分层架构

遵循领域驱动设计与端口适配器模式，所有依赖一律向内指向纯领域核心：

```text
校验/
├── src/
│   ├── domain/                  # 【领域层 Domain】绝对纯净，零外部依赖
│   │   ├── model.py             # 核心值对象: CheckStatus, DimensionType, DimensionResult, VerificationReceipt
│   │   └── verifier.py          # 领域聚合根: SnapshotVerifier (6大黄金维度纯规则引擎)
│   │
│   ├── application/             # 【应用层 Application】用例编排与跨系统协调
│   │   └── use_cases.py         # VerifySnapshotUseCase (文件IO适配领域), CheckConsistencyUseCase (系统一致性)
│   │
│   └── adapter/                 # 【适配器层 Adapter】外部驱动接口
│       └── cli.py               # 命令行统一入口: 支持 --match (单场安检) 与 --system (全库巡检)
│
├── 测试/                        # 【测试层 Tests】镜像单元与端到端测试
│   ├── test_domain.py           # 领域层值对象与规则单测
│   ├── test_use_cases.py        # 应用层用例与磁盘IO单测
│   └── test_adapter.py          # 适配器 CLI 参数、退出码与 JSON 输出端到端测试
│
└── 文档/                        # 【文档层 Docs】权威规范与演化指南
    ├── ARCHITECTURE.md          # 本架构说明书
    └── 数据完整性验收标准手册.md # 6 大黄金维度法定验收标准
```

## 三、6 大黄金维度法定判定标准

| 维度 | 检查项 | 法定合格标准 (PASS) | 判定失败行为 (FAIL) |
| :--- | :--- | :--- | :--- |
| **1. 基础战绩与攻防数据** | 主客队名、联赛名称、积分 | 字段存在且非空字符串 | 阻断，报基本信息残缺 |
| **2. 欧洲指数 (1X2)** | 威廉、立博、365 初即盘 | 包含有效赔率记录或时序 | 阻断，报欧指缺失 |
| **3. 亚洲让球盘 (AH)** | 澳彩、皇冠、365、易胜博 | 包含主流让球盘口与两端水位 | 阻断，报亚盘缺失 |
| **4. 大小球进球数 (OU)** | 主流四家初即盘 | 包含大小球进球数盘口水位 | 阻断，报大小球缺失 |
| **5. 分钟级变盘流水时序** | 升降盘与水位变动历史 | **有效变盘记录或切片 $\ge 3$ 行** | **物理熔断 (exit 1)**，严禁两端冒充时序 |
| **6. Crown 皇冠全指数波胆** | 0:0 至 4:4 比分赔率矩阵 | 包含全波胆指数文本或结构化数据 | 阻断，报波胆缺失 |
| *容错维度: 微观伤停* | 缺阵名单 | 包含具体球员缺阵原因 | **标记 WARN (不阻断)**，置顶警示伤停未核实 |

## 四、演化路线：`scripts/` 的弱化与淘汰三步走

1. **第一阶段（已完成）**：建立 `校验/` 模块，将 `scripts/check_consistency.py` 重构为薄垫片（仅 26 行），底层全面委托给 `校验/src/adapter/cli.py`；
2. **第二阶段（当前）**：所有新增技能、工作流提示词及命令强制直接调用 `校验/src/adapter/cli.py`；
3. **第三阶段（未来）**：当遗留爬虫工具彻底清退或迁移后，正式移除 `scripts/` 目录，全库只保留 `算法/`、`校验/`、`skills/`、`data/`、`memory/` 等高内聚核心模块。
