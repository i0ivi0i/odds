# ADR 0001: 赛前资料完整性闸门（齐全且对得上才能代）

## 状态 (Status)
已采纳（2026-10-06 再修订）：闸门看资料齐不齐、对不对，不看网站姓什么。

## 背景与问题陈述 (Context)
盘口与赔率时序默认走球探网（titan007），因为通常最全：伤停、亚盘/欧指流水、14 家机构。曾用澳客网、体彩官方三项去顶，当时缺伤停、缺国际机构流水，或数据错误，硬推会把空伤停写成「全主力」。问题是**缺、错、少**，不是「第二家网站永远不许用」。

## 决策内容 (Decision)
1. **接口契约**：推演只消费标准 `agent.analysis` 结构。
2. **盘口主源**：球探网（titan007）。线上抓取默认 `/browseros-neo` 直开球探页，禁止先跑脚本命令。
3. **脚本通道**：已被握手拦截，不得当正式入口。残页/空流水必须马上置顶提醒并贴页上原句，然后继续十步；禁止静默、禁止跳过。`scripts/sporttery-sniper` 仅保留解析与单测。
4. **其他来源能不能代**：当场该有的亚盘/欧指流水、机构盘口、主客场/近6数字**齐全、没错、和对家该有的对得上** → 可以代。错了、空了、少了一截（只有体彩三项、空时序、写死假盘）→ 不能代。缺验收门：置顶提醒并贴页上原句；当面聊天先停，等主人回再继续；定时任务置顶后继续十步，不准跳过。伤停格「暂无数据」不是缺数据，不能代也不挡十步。
5. **体彩官方网关**：核对竞彩场次编号（如周二001）、当日是否开售、节假日休市。三项静态赔本身不是完整盘口资料。接口见 `config/datasources.json` 的 `sporttery_match_codes`。
6. **伤停**：正式分析以球探分析页「阵容情况」为准。英超 FPL / Big Balls 只覆盖部分俱乐部联赛，空返回不得写成无伤停。

## 收益与代价 (Consequences)
### 收益：
- 不再用残缺骨架冒充完整赛前资料。
- 齐全且对得上的来源可以代，不必死卡网站名。
### 代价：
- 必须先用 `/browseros-neo` 把验收门四项抄全再推；缺验收门必须马上提醒并贴页上原句，不能静默硬推。当面聊天先停，等主人回再继续；定时任务置顶后继续十步，不准跳过。伤停空表不挡十步。
