# ADR 0001: 多源热备数据适配器架构 (Multi-Source Odds Failover Architecture)

## 状态 (Status)
已提议 / 决策中 (Proposed)

## 背景与问题陈述 (Context)
目前系统的盘口与赔率时序主要通过单一数据中继源（球探 titan007）抓取。虽然其数据极其完整、零成本且涵盖 14 大机构，但存在明显的单点故障风险（Single Point of Failure, SPOF）：
1. 若该网站因域名封锁、服务器故障或关停倒闭，将导致整个预测推演流水线停摆。
2. 伤停数据虽已解耦至官方 FPL 及专业体育 API，但核心赔率骨架仍需高可用的备用管线保障。

## 决策内容 (Decision)
采用**插座式适配器多源热备架构 (Adapter Hot-Failover Pattern)**：
1. **接口契约归一化**：推演核心与大模型只消费标准 `agent.analysis` 结构，完全屏蔽底层抓取来源。
2. **双轨数据源定义**：
   - **主数据源（Primary）**：球探网（titan007），提供毫秒级、深历史时序。
   - **备用数据源（Secondary）**：国内老牌数据平台（澳客网 / 雷速），提供同维度的欧亚盘口与体彩映射。
3. **自动熔断与故障切换策略**：
   - 当主数据源连续 2 次请求超时（>3秒）或返回 50x / 404 错误时，系统在 1 秒内无缝切换至备用数据源。
   - 输出报告与日志中必须显式标明当前实际启用的数据源（如 `[数据源: 备用热备(澳客网)]`），保证推演透明诚信。
4. **统一命名与机构映射**：
   - 底层适配器负责将不同网站的机构编号（如威廉、平博、365）和球队别名映射为统一标准名，杜绝编号冲突。

## 收益与代价 (Consequences)
### 收益：
- 彻底根除单点依赖风险，哪怕主源网站永久倒闭，系统推演业务零中断。
- 零额外资金成本，充分复用国内经过 20 年检验的成熟体育数据基础设施。
### 代价：
- 需维护两套网站的解析逻辑与球队名对齐词典。
