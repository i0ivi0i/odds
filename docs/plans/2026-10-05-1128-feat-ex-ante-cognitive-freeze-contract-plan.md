## Goal Capsule

- **Objective:** 彻底根除足彩推演中“首选与次选倒挂”及赛后复盘“事后诸葛亮脑补”的顽疾。建立开球前不可逆的「结构化认知契约卡」，在赛前冻结大模型内心真实纠结、排除依据与反证条件，并在赛后实现基于契约底账的精准倒查与认知自进化。
- **Means:** 实施“结构化认知契约卡三要素（内心纠结与排除理由、庄家博弈演绎链、可推翻反证条件）+ 每日记忆后台 100% 静默封存 + 前台六列表极致纯净解耦 + 赛后未中首选场次精准倒查审计”全套纯 Prompt 与 Markdown 规范，零业务代码驱动系统认知自愈 (KTD1, KTD2, KTD3)。
- **Product Authority:** 遵循主人最高立宪铁律：严禁编写任何推演决策、倍率破译或死尺子门禁代码；系统优化严格遵循“主要做减法、其次做微调、慎重做加法”原则；所有推演决策与自进化全权依托大模型主观意图与 Graphify 拓扑联动。
- **Stop Conditions:** 技能手册微调完毕且语法自洽；单场分析契约卡规范确立；每日记忆写入规范清晰；赛后未中首选倒查审计规则明确；`py -3.13 scripts/check_consistency.py --print-ok` 满分通过，图谱 0 孤岛。

## Product Contract

### Summary
本方案为足球倍率分析推演系统确立开球前不可篡改的「结构化认知契约卡」规范。在单场深度分析完成时，大模型必须冻结三大核心心路要素：① 内心纠结与排除理由（为何放弃数学最高项或选次选）；② 庄家博弈演绎链（为何判定诱或阻）；③ 可推翻反证条件（具体场上何种走势证明赛前逻辑被推翻）。该契约卡 100% 静默锁在每日记忆 `memory/YYYY-MM-DD.md` 作为只读硬底账，推给主人的赛前六列表保持清爽纯净；赛后复盘时，首选命中场次简明汇总，仅对「未中首选」的场次调取契约卡逐字核对，区分概率方差与认知缺陷，将真教训回流至 `MEMORY.md`。

### Problem Frame
1. **决策前心路流失（形式主义压缩）**：在 10-04 欧国联实战中，阿塞拜疆与威尔士两场比赛点概率分别为 38% vs 36%，系统最后落槌时将较高概率的一侧排为次选、将较低概率的平局排为首选（首选与次选倒挂）。但由于每日 memory 摘要此前仅浓缩了干瘪的数字结果，没有在开球前不可逆地冻结大模型内心真实的交锋纠结、排除依据与反证条件；
2. **复盘缺乏客观凭据（后见之明偏见）**：依据 Aiyer et al. (2023) 与 Baron & Hershey (1988)，人在知道比赛结果后会自动产生严重的结果偏见（Outcome Bias，效应量高达 d=1.10），自动编造一套虚假的记忆来合理化赛果。缺乏赛前预注册的决策理由，赛后复盘只能沦为凭空脑补；
3. **缺乏反证条件的检验抓手**：没有在赛前明确“出现什么情况证明我今天看走眼了”，导致复盘时无法客观区分究竟是“已知风险兑现（概率方差波动）”还是“庄家意图误读（系统真盲区）”。

### Key Decisions
- **KD1. 认知契约卡采用四要素全景高密度精炼格式**：每场分析强制产出「内心纠结与排除理由、临界拍板依据 (Tie-Breaker)、庄家博弈演绎链、可推翻反证与对立面抗辩」，兼顾因果完整性与文档可维护性。
  *(session-settled: user-directed — chosen over 全量长文堆砌或仅记三要素: 完整闭环临界拍板稻草与反方抗辩，彻底杜绝思维盲区。Governs R1, R2)*
- **KD2. 前后端完全解耦与后台纯净封存**：契约卡 100% 静默写入每日 `memory/YYYY-MM-DD.md` 作为只读底账；推给主人的赛前六列表严格保持干净整洁，绝不向聊天界面倾倒长篇契约文本。
  *(session-settled: user-directed — chosen over 前台全量展开或双层折叠: 遵守主人 clean 审美与防干扰铁律，复盘或追问时才调出。Governs R3, R4)*
- **KD3. 赛后复盘采用失误场次精准倒查机制**：首选命中的场次简要汇总；仅对「未中首选」的场次调出赛前契约卡逐字核验，抓取真实思维盲区。
  *(session-settled: user-directed — chosen over 全量场次拉网或机械打分: 抓大放小，集中算力深挖真正失误根因。Governs R5, R6)*

### Requirements

#### 模块一：单场推演契约卡生成规范 (Ex-Ante Contract Generation)
- R1. **认知契约卡四要素完备性**：在 `skills/deep-analysis/SKILL.md` 单场 10 步分析完成后，必须在综合评估后独立生成「认知契约卡」，严格包含：
  - ① **内心纠结与排除理由**：面对胜/平/负概率分布，当时大脑在哪些项之间产生了权衡纠结？放弃数学最高概率项、选择次选或并列项的核心逻辑依据是什么？
  - ② **临界拍板依据 (Tie-Breaker)**：当两端概率差距极小（≤3%）或证据打架时，究竟是哪家公司的哪一个具体盘口异动/关键事实成为了拍板首选的“最后一根稻草”？
  - ③ **庄家博弈演绎链**：从初盘到终盘的升降变动中，大脑判定庄家核心意图是在“诱买”还是“赶筹阻盘”的一句话因果假说；
  - ④ **可推翻反证与对立面抗辩**：明确列出“对立面赛前最危险的战术杀招是什么？且赛前盘赔若出现何种逆向异动（如临场退盘高水、欧亚脱节等）或名单重大突变，即证明赛前攻防基准与庄家博弈假说被彻底推翻”。
- R2. **Worker 子任务回传契约格式**：Worker subagent 在执行完单场深度分析后，回传的结构化数据与 memory 摘要中必须完整携带该「认知契约卡」，不得因多场并发而偷懒精简。

#### 模块二：每日记忆落盘与前台解耦规范 (Memory Freezing & Delivery Decoupling)
- R3. **每日记忆静默完整封存**：编排 subagent 在收齐各场结果后，统一将各场摘要写入 `memory/YYYY-MM-DD.md` 的 `## 深度分析` 中。每场摘要格式固定包含：欧指、亚盘、大小球、综合评估、泊松比分、点概率、图谱武器以及**独立的「【认知契约卡】」段落**，作为开球前不可篡改的只读底账。
- R4. **前台六列表极致纯净**：推给主人的赛前精选六列表报告保持极致大白话人话剧本，表格内部与表下严格不输出冗长的契约卡文本，确保交互界面零噪音。

####模块三：赛后精准倒查审计规范 (Post-Review Audit & Evolution)
- R5. **失误场次定向调取与逐字倒查**：在每日 10:30 执行 `skills/post-review/SKILL.md` 复盘时，首选命中的场次进行简明对账；对所有「未中首选（打出次选或冷门）」的场次，必须从当日 memory 的 `## 深度分析` 中精准提取该场赛前冻结的「认知契约卡」。
- R6. **Aiyer 决策审计与双轨归因**：复盘时对照实际赛果与比赛关键事件时序，进行双轨审计：
  - 轨 A（方差判定）：赛前三端分析、盘水防守与攻防基准完全自洽，对立面客观战术杀招亦有充分预警，赛果仅属于足球低概率物理方差兑现；判定为“决策过程严密合规（正常概率方差）”，不妄动底层规则；
  - 轨 B（认知盲区）：若当时采纳的【排除理由】或【庄家博弈演绎链】被物理事实打脸（如误把阻盘当诱盘、误判主力伤停影响），判定为“决策认知缺陷”；
- R7. **教训靶向回流中枢**：针对轨 B 的决策缺陷，提炼具体可操作的思维校准规则，合并沉淀至 `MEMORY.md` 的「策略调优记录」，完成系统认知自进化闭环。

### Scope Boundaries
- **In-Scope**:
  - `skills/deep-analysis/SKILL.md` 增加契约卡生成规范与 Worker 回传标准；
  - `skills/recommendation/SKILL.md` 明确契约卡在 memory 的落盘格式与前台纯净解耦；
  - `skills/post-review/SKILL.md` 确立赛后未中首选场次的定向契约卡调取、Aiyer 审计与教训回流规则；
  - `AGENTS.md` 同步微调第 4 条与第 7 条规范，明确契约卡在工作流中的宪法级地位。
- **Out-of-Scope (Non-Goals)**:
  - 严禁编写任何 Python 代码或自动化评分脚本实现该功能（坚守纯 Prompt 与 Markdown 总战略）；
  - 严禁向前台聊天窗口倾倒冗长的契约卡文字；
  - 不篡改历史已完成的比赛记录，新规则自下一次推演起严格生效。

### Success Criteria
- 每次赛前分析在开球前均在每日 memory 中留下不可篡改的「认知契约卡」四要素记录；
- 赛后复盘能准确还原开球前决策依据，未中首选场次 100% 具备赛前心路对账审计记录；
- 系统一致性检查 `py -3.13 scripts/check_consistency.py --print-ok` 满分通过，文档图谱 0 孤岛。

## Planning Contract

### Key Technical Decisions
- **KTD1. 基于 Prompt 规范而非代码实现契约卡约束**：在技能手册中固化提示词约束模板，大模型在生成摘要时自然内生结构化契约卡，不引入任何多余代码。
  *(session-settled: user-directed — chosen over 编写验证脚本: 遵守系统最高立宪零代码铁律。Governs R1, R2)*
- **KTD2. 记忆落盘契约与编排收集器对齐**：契约卡作为 Worker 返回 JSON 中 `memory_summary` 的标准组成部分，由编排 subagent 集中写入，确保单点写入无并发冲突。
  *(session-settled: user-directed — chosen over 各Worker并行写入: 彻底避免并发冲突导致场次丢失。Governs R3)*
- **KTD3. 复盘审计与 MEMORY.md 调优记录的闭环打通**：在 `post-review` 的步骤 4 中明确定义契约卡倒查流程，若识别出系统认知缺陷，强制执行去重合并更新写入 `MEMORY.md`。
  *(session-settled: user-directed — chosen over 泛泛总结: 确保每一次实战失误都转化为系统长期资产。Governs R6, R7)*
