# 倍率分析推演工作流

备份与版本控制遵循 Git 优先与极简原则：修改直接依赖 Git 版本控制，本类任务不新建 `.bak` 文件。**切忌教条繁琐**：不要在每次回答前反复执行繁重的全局 `.bak` 扫描与零残留自证汇报，也不要向主人喋喋不休汇报「.bak 数量为 0」，过度繁文琐节会严重拖慢响应速度。Git 基线已足够提供保障，严守极简原则，专注于业务推演与核心思考。

## When to Use

仓库是 `倍率分析推演`，或主人要读盘、七列表、报答案复盘、改 MEMORY 战绩时用。不要用 `odds-1x2-sniper` 的一行【胜平负】交差。

在仓库里想、答、分析、推演，都走这套。TOOLS.md 是数据采集与时序武器库，图谱是地图，当场三端才是计算。
