# 赛后复盘（post-review）

获取已完场比赛的结果，对比推荐记录，计算命中率，分析失误原因，更新长期统计。

## 论文应用回检

原文在 `docs/论文/`（PDF 才是原文；`README.md` 只是索引）。复盘时必须打开对应 PDF 或用 `graphify query` 取回带 `source_location` 的原句再引用。**禁止用案例号、门禁名、索引里的「一句话」代替原文。** 论文指导怎么复盘，不证明本项目能赚钱。

**paper-application-v2**：十九篇通过 `docs/论文/README.md` 对应到初筛、十步、推荐记录和本节回检。研究不另设下注门禁，也不把让球优先、RLM、诱阻推演改成中性观察。每场追查实际应用的方法对首选有何帮助或误导，原句用于有争议的方法核对，不要求无关论文逐篇打卡。

| 何时 | 打开哪份原文 | 当场必须写清 |
| --- | --- | --- |
| 揭比分之前 | `2023_Aiyer_结果偏见与决策评价.pdf` | 当时三维落槌是否自洽；过程分与结果分分开写 |
| 给胜平负打分 | `2019_Wheatcroft_足球概率预测评分.pdf` | 不当「猜中/没猜中」一本账；有概率就记概率质量 |
| 切样本、贴标签 | `2023_Hewamalage_预测评估陷阱与最佳实践.pdf` | 禁止赛后按场次代号/比分再切出假规律 |
| 推平却分出胜负 | `2021_Dimitriadis_稳定可靠性图_CORP.pdf` | 30% 的平意味着七成分胜负仍正常；单场不足以降权 |
| 想改规矩 | `2006_Giacomini_条件预测能力检验.pdf` | 先冻结假设，用后面没见过的球检验；状态标「待验证」 |
| 比较新旧方法 | `2023_Choe_序贯预测者比较_arXiv_v6.pdf` | 看累计差异，不看单日情绪 |
| λ / 状态大改 | `2025_Macri_足球贝叶斯加权动态模型_arXiv.pdf` | 稳定时借用历史，核实重大状态变化后允许及时调整，不因单场输赢重设 |
| 想加例外条款 | `2026_Wilkens_德甲预测与滚动验证.pdf` | 简单模型优先；例外必须滚动样本外仍成立 |
| 看庄家有没有吃偏见 | `2004_Levitt_NBER_w9422.pdf` | 问客胜/冷门一端当时价有没有被系统性看轻 |

每场复盘报告至少引用 **1 句原文**（带文件名）。没有论文锚点的「教训」不得写入 `MEMORY.md` 永久条目。

## 闭环验收（处理完成与方法证据分开）

逐项按真实证据标已核、缺失或待办，不预填全勾。分别保存「处理状态」「方法证据」「投递状态」：可恢复的抓取、核对或写入尚未做完，记「仍有待办/执行失败」；全部可执行核对已做且仅永久缺失赛前资料，记「已完成但部分指标不可评分」，列出缺失及影响，不无限重跑，也不称完整方法验证。资料齐备且全部核对通过才记「已完成」。已知答案标事后审计，不能补成盲审；证据不足不能升级永久规则，但不抹掉已核实的首选结果。

- [ ] 先审过程，再揭比分（Aiyer；若答案已在先前上下文出现，标事后过程审计，不作盲审）
- [ ] 胜/平/负三端写清为何出、为何不出；推平写清客胜为何更弱（检查赛前留存是否做到，缺则报告缺口，不赛后补写成原判断）
- [ ] 至少一句论文原文（文件名 + 原句），不是案例号
- [ ] 布莱尔分，或写明「无概率，只记命中」（Wheatcroft）
- [ ] 待验证表已回检（支持/反对/无触发），不满 8 场不改永久规矩
- [ ] `graphify query` 能命中本场用到的论文节点
- [ ] 对本场实际应用的方法记录作用与失误位置；未涉及的论文不为凑数填表
- [ ] 欧亚折合与造热：写了折合 vs 实盘；造热只记疑点；未把升盘降水写成必出对面

## 输入

- 需要复盘的日期（默认：昨天）
- 当日推荐记录（从 memory 中读取）

## 执行步骤

### 步骤 1：读取推荐记录

从每日记忆中获取需要复盘的推荐。**若 `memory/{复盘日期}.md` 不存在**，视为无推荐记录，直接执行下方「如果没有找到推荐记录」的后续逻辑（告知主人、写入 ## 赛后复盘、结束）。

```
memory_get memory/{复盘日期}.md
```

找到推荐部分：在 memory 文件中查找所有**二级标题**为以下之一的 section：

- `## 推荐`
- `## 推荐（*)`（\* 为时间，如 14:25）

旧记录沿用原口径；`paper-application-v2` 按matchId取每场开球前最后有效发布并匹配其分析版本，早批未刷新的场次不丢失。已知赛果后的补写不得覆盖赛前首选、概率。研究统计按 `matchId+发布版本+指标` 去重更新，补赛果不能重复累加。

**区分精选场次和候补场次**（按实际赛前版本分别提取）：

- 精选场次：提取联赛、主队、客队、推荐内容、信心度、比赛ID
- 候补场次：同样提取，但标记为「候补」；缺次选、概率或具体玩法时只按已有赛前值核对，缺失写「不可评分」，绝不从赛后结果补造。

**复盘主体 = 精选场次**（进入累计推荐口径，不等同于已核实主人实际下单）。候补场次也逐场做赛前过程缺口与结果核对，单独展示作为观察组，不计入主要命中率统计；逐场表须覆盖两组合计全部 `matchId`，同时报精选、候补和全量的首选与覆盖数量。

**补追待复盘场次**：检查前 3 天（{复盘日期-1} 到 {复盘日期-3}）的 memory 文件，如果其中有标记为「待复盘」的场次，一并纳入本次复盘。这些场次：

- 在复盘报告中标注为「补复盘（原推荐日期：{日期}）」
- 命中率计入原推荐日的统计；更新 MEMORY.md 累计值时合并入原推荐日贡献即可，**同步更新原日该场待办状态、最终结果和补盘记录位置，其他场次保持不变；原日统计贡献由同一写入者按新值替换，不能在两天重复入账**
- 命中率和泊松 Top 6 校验正常计算

如果没有找到推荐记录（当日 + 待复盘均无）：

- 告知主人「{日期}没有推荐记录，无需复盘」
- **仍须在 `memory/{复盘日期}.md` 中追加写入**（若文件不存在则创建）：
  ```
  ## 赛后复盘
  {日期} 无推荐记录，无需复盘。
  ```
  以便 Heartbeat 不再重复触发复盘补漏。
- 结束流程（不执行步骤 2–9，不更新 MEMORY.md）

### 步骤 1.5：先审过程，再揭比分（Aiyer 决策审计与认知契约卡对账）

取赛果之前，只读当日 `## 深度分析` 与推荐理由（三维落槌、关键点、疑点、矛盾，**特别是赛前冻结的「图谱认知基因」与「认知契约卡」**）。**先列本批全部 `matchId`，精选与候补均逐场提取认知基因与认知契约卡（内心纠结与排除理由、临界拍板依据、庄家博弈演绎链、可推翻反证与对立面抗辩），写两行并保存可回读的过程审计记录，之后才调用抓取赛果**；不能只审精选，也不能把事后写在赛果前面的章节冒充“先审”。已在先前对话、日志或来源中看到赛果的场次标「已知答案的事后审计」，不得宣称严格先审后揭。每场：

- 过程：当时胜/平/负三端是否写清「为何出/不出」；证据是否打架；**赛前调用的图谱武器（节点 ID）与当场盘赔特征是否匹配自洽**；认知契约卡中排除最高概率项或选择次选的依据是否充分。
- 待揭晓：还不知道赛果，不打命中分

取完赛果后，过程分保持不动，另写结果分。禁止用赛果改写「当时其实已经看出来」。对账验真规则：
1. **若首选命中**：验证了该图谱武器与推演因果链在当类盘面的有效性，记为正向样本；简明汇总即可；
2. **若首选失误（打出次选或冷门）**：强制调出赛前冻结的「认知契约卡」，启动 Aiyer (2023) 决策双轨归因审计：
   - **轨 A（方差判定）**：赛前推演逻辑、盘水咬合与攻防基准完全自洽，对立面客观战术杀招亦有充分预警，赛果仅属于足球低概率物理方差兑现；判定为“决策过程严密合规（正常概率方差）”，不妄动底层规则；
   - **轨 B（认知盲区）**：赛前的【排除理由】或【庄家博弈演绎链】是否被物理事实打脸（如因过度提防诱盘而错误颠倒了高概率项、误判主力伤停影响、误把阻盘当诱盘）？若是，判定为“系统决策认知缺陷与排序偏置”；
3. **自进化靶向回流**：针对轨 B 的决策缺陷，当场提炼出具可操作性的思维校准实战规则，合并更新写入 `MEMORY.md` 策略调优记录，彻底闭环认知自愈自进化。

### 步骤 2：获取比赛结果

从推荐记录中取出每场比赛的比赛 ID，使用 `scripts/sporttery-sniper` 逐场获取复盘数据和最终赛果：

```bash
cd scripts/sporttery-sniper
npm run review -- {matchId} --format agent-json
```

从返回的 JSON 中读取赛果信息：
- `context`：包含全场比分、半场比分、进球数与完场状态
- `detail`：包含主队、客队、完场比分等结构化数据

逐场获取，如遇偶发网络超时重试一次。

若推荐记录中比赛 ID 丢失或需要查看整日开售赛果，可指定销售日同步赛程赛果：

```bash
cd scripts/sporttery-sniper
npm run schedule -- --date {昨日销售日} --format agent-json
```

### 步骤 3：逐场核对

对每场推荐的比赛：

1. **匹配比赛**：通过主客队名在赛果列表中找到对应比赛
2. **获取比分**：记录最终比分（如 2:1）
3. **判断命中**：

**胜平负**：

| 推荐类型               | 命中判断规则                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 固定 2 项（首选+次选） | 推荐为 首选 + 次选。**核心首选命中**：实际赛果与首选完全一致才算首选命中。**双选覆盖命中（风控备选参考）**：首选或次选任一命中即为覆盖命中（其中仅次选命中属于备选覆盖，不得把覆盖命中冒充核心首选命中）。赛果判定：主胜=主队进球>客队，平局=主队=客队，客胜=客队进球>主队。 |

**亚盘完整规则**：

设净胜球 = 主队进球 - 客队进球，盘口 H = 主队让球数（正值主让，负值主受让）。调整后净胜球 D = 净胜球 - H。

| 盘口类型     | 举例                | 上盘（让球方）赢 | 走水       | 下盘（受让方）赢 |
| ------------ | ------------------- | ---------------- | ---------- | ---------------- |
| 整数盘       | -1, 0, +1           | D > 0            | D = 0      | D < 0            |
| 半球盘       | -0.5, -1.5, +0.5    | D > 0            | 不可能走水 | D < 0            |
| 四分之一球盘 | -0.75, -1.25, +0.25 | D > 0（全赢）    | —          | D < 0（全输）    |
| ↑ 同上       | ↑                   | —                | —          | —                |

**四分之一球盘详细规则**（-0.75 = 半球/一球, -1.25 = 一球/球半, +0.25 = 平手/半球 等）：

- 将盘口拆为两注：H₁ = H - 0.25, H₂ = H + 0.25
- 分别按整数/半球盘规则判定两注的输赢
- **全赢**：两注都赢 → 命中
- **赢半**：一注赢 + 一注走水 → 命中（半），统计计 0.5 场命中
- **输半**：一注输 + 一注走水 → 未中（半），统计计 0.5 场未中
- **全输**：两注都输 → 未中

**大小球完整规则**：

设总进球 T = 主队进球 + 客队进球。

| 盘口类型     | 举例       | 大球赢                         | 走水     | 小球赢   |
| ------------ | ---------- | ------------------------------ | -------- | -------- |
| 半数盘       | 2.5, 3.5   | T > 盘口                       | 不可能   | T < 盘口 |
| 整数盘       | 2, 3       | T > 盘口                       | T = 盘口 | T < 盘口 |
| 四分之一数盘 | 2.25, 2.75 | 拆两注，规则同让球四分之一球盘 | —        | 同上     |

**大小球首选/次选（新口径）**：

- 若推荐记录中大小球写为「首选 …；次选 …」：
  - **严格命中（用于统计）**：只判定**首选**是否命中（次选不计入命中率分子分母，仅用于覆盖展示）。
  - **覆盖命中（用于风控评估）**：首选或次选任一命中则记为覆盖命中（可在逐场报告里单独写一行，不计入主命中率）。
- 若推荐记录中大小球仅有单一方向（旧记录）：按旧规则直接判定该方向命中即可。

4. **标记结果**：命中 / 未中 / 走水 / 赢半 / 输半

**走水和半赢半输场次的统计规则**：

- **走水**：不计入命中率（分子分母均排除），复盘报告中单独列出「⏸ 走水 N 场」
- **赢半**：分子 +0.5，分母 +1
- **输半**：分子 +0，分母 +1
- 命中率 = (全赢场次 + 赢半场次×0.5) / (总推荐 - 走水场次)

5. **组合推荐处理**：如果是组合推荐（如「主胜 + 大2.5球」），按玩法拆分分别判断命中，计入**各玩法命中率**（玩法类型：胜平负、亚盘、大小球、进球数；让球推荐计入亚盘）；旧版在"推荐场次"维度仍算1场，任一玩法命中按旧口径保留；新研究各玩法独立评价，不用其他玩法命中替代胜平负首选命中。**标注「⚠️ 观望」的玩法**：该场在该玩法上不计入推荐数、不计入命中数（分子分母均排除），与 recommendation 的「多玩法统计规则」一致。
6. **比分预测核对**：将实际比分与推荐比分对比（泊松相关比分最多 6 个）
   - 完全命中其中一个 → 标记 🎯 精准命中
   - 未命中但总进球数一致 → 标记「进球数正确」
   - 完全不中 → 标记「比分未中」

- 从当日 memory 读取**赛前实际发布版本**的「独立泊松比分简表」，只检查实际比分是否落在其 Top 6；不再读取或要求完整 0:0～7:7 概率表。若缺 λ/Top 6 或仅有盘赔约束的推荐比分，记「赛前未记录／不可评分」，不能拿后者代算泊松命中，也不能赛后按比分补算当成赛前预测。
- **两套比分增强**：若该场在 ## 深度分析 中存在「与大小球同方向 Top 3」——即当时有大小球 vs 泊松矛盾、存了两套比分——则分别检查实际比分是否命中「整体 Top 3」或「同方向 Top 3」，用于对比矛盾场次的方向选择。

7. **串关核对**：从当日 memory 读取串关组合建议，逐个组合判断
   - **2 串 1**：两场推荐都命中 → 串关命中；任一未中 → 串关未中
   - **3 串 1**：三场推荐全部命中 → 串关命中；任一未中 → 串关未中
   - 比分串关：两场比分都精准命中 → 串关命中
   - 混合串关（如 1 场比分 + 1 场胜平负）：各自按对应规则判断，全部命中才算串关命中
   - 记录每个组合的预期赔率和实际结果

### 步骤 3.5：分析质量自评（泊松模型质量）

用以下指标评估比分模型质量：

- **Top 6 命中**：实际比分是否出现在泊松比分简表 Top 6 中？
  - 记录实际比分在Top4、Top6之内或之外，保留检查λ的线索；单场排名不独自判模型优秀或失效
- **λ 偏差方向**：记录实际总进球与预期总进球（λ1+λ2）的差；累计同类样本再判断系统性偏高或偏低
- **两套比分场次**：若该场深度分析中存在「与大小球同方向 Top 3」，在逐场输出中写「整体 Top3 命中/未中；同方向 Top3 命中/未中」，便于长期对比两套策略

### 步骤 3.6：概率打分（有数才算，不当对错本）

命中率只说明猜中没猜中。有赛前主胜/平/客胜三个概率时，另算布莱尔分（Wheatcroft）：

- 打出哪项，那项记 1，其余记 0
- 分数 = (主概率−主实际)² + (平概率−平实际)² + (客概率−客实际)²，越低越好
- 三个概率须是赛前已留的点概率，在0到1且合计1（声明舍入误差）。只有区间就记「缺赛前点概率」，不在赛后取中点造数；方向命中与推演过程仍正常复盘。市场、独立泊松、综合判断分源评分。
- **没有三个概率就写「无概率，只记命中」**，不许编数字
- 首选命中与布莱尔分分开写，不得用「首选+次选任一算中」代替概率分

新研究记录另列首选命中、双选覆盖、观望数和缺概率数，不改旧累计口径。可加对数损失 `-ln(实际结果的赛前概率)`，零概率而发生时为无穷，不偷偷裁剪；Wheatcroft并非证明布莱尔唯一最优。以上通过工具计算。Dimitriadis用于定期比较主／平／客概率和实际频率，校准拟合用过去、评价用以后，不拿单场兑现与否否定概率。

**4a. 关键判断回顾（每场都做）**

回顾深度分析第 9 步的「关键点/疑点/矛盾」，逐一与实际结果对照：

- 当时识别的**矛盾信号**——实际结果支持了哪一方？
  - 例：「亚盘看好主队但欧指偏向平局」→ 实际结果是平局 → 欧指信号更准
- **伤停与战意回检**——对照赛前记录的来源和时点：实际首发、缺阵、替补和轮换是否与当时信息相符；结果需求是否被误读成全力投入；盘口是否已消化信息，是否重复计入。区分赛前可知、赛前未知和赛中新发生，不能仅凭输赢倒推“战意不足”。
- 当时标注的**风险点**——有没有真的发生？
  - 例：「轮换风险」→ 确实轮换了 3 名主力，导致进攻乏力
- 当时的**核心判断依据**——赛后来看是否成立？
  - 例：「看好主胜的核心依据是主场 5 连胜」→ 但对手近 5 场客场 4 胜 1 平，均值回归更该看客队
- **庄家诱盘、让球防守与 RLM 信号回检**——先遮赛果审当时记录的胜／平／负依据、资金假设与反证，再核对结果；既查忽视末段修正，也查过度追随末段而错弃原首选。高主赔不能证明主胜无人防范，下盘保护不唯一指向平局，小球不排除热门小胜。命中只能说明该场方向兑现，不倒证资金流、庄家动机或真实净赔付；缺注额也不取消有依据的方向假设。
- **泊松方向校验**：从该场深度分析摘要读取「大小球 vs 泊松比分」或其他方向矛盾。结合赛果注明：当时泊松方向、盘赔方向、推荐方向分别是什么，实际结果支持哪一侧；不再复盘 EV。
- **大小球盘口轻量锚定（OU Anchor）**（若摘要中有）：从该场深度分析摘要的「泊松比分简表」头两行读取 `大小球盘口锚定 = 启用/未启用（w=0.25, line=..., λtot: X→Y）`。逐场报告中必须带一行，便于长期评估锚定是否在“帮忙还是拖后腿”：
  - 启用：记录 line（含 2.25→2.5 / 2.75→3.0 的近似结果）、锚定前后 λtot 变化（Δλtot=Y−X）
  - 未启用：写「未启用」
  - 若摘要缺失该字段（旧格式）则写「无记录（旧摘要）」并不计入锚定统计

输出：每场 2-3 句话的判断回顾。

**4b. 失误分析（仅未命中场次）**

先对所有场次检查数据与执行，再对未命中场次分析判断。错因分为资料错误（比分/样本/截至）、执行遗漏或泄漏、三端裁决错误、概率估计偏差、赛前不可知的偶然事件，可并列但各需证据。执行失败先修输入与验收，不用新增盘口口诀掩盖；偶然性不是免检理由。已知答案复演、泄漏及时间越界记录只用于过程审计，不作为合格盲测或方法提升样本，披露无效数及原因且不覆盖历史赛前版本。

对未命中的场次（特别是未中首选），调用 AI 大脑的大局观与因果逻辑，强制调取赛前冻结的【认知契约卡】进行深度倒查，动态调用全库 19 篇学术论文中最契合当场实际的理论（如 Aiyer 过程解耦、Levitt 偏见收割、Constantinou 亚盘防守、2605.30209 异动假摔、Wheatcroft 概率排序、Dimitriadis 可靠性等，不设刻板死尺子固定配对，由 AI 依据事实灵活研判）：
- **对照【内心纠结与排除理由】**：当时为什么放弃了实际打出的一侧？当时采纳的排除理由是事实证据还是主观过度反应？是否存在两端概率差距极小（≤3%）时的首选次选排序偏置？
- **对照【临界拍板依据】**：当时作为拍板定音的那根具体盘口异动/小数据稻草，赛后证实是机构真实的做市信号还是散户噪音与假摔诱导？
- **对照【庄家博弈演绎链】**：当时认定的诱买或阻盘假设，赛后来看庄家真正防守的到底是哪一端？是否误把防守当成了诱盘？
- **对照【可推翻反证与对立面抗辩】**：赛前预见的反证走势或反方最强杀招是否真实发生？若真实发生，归为已知方差（过程合规）；若未发生却依然失误，深挖底层攻防基准与排序盲区。
- **论文理论动态诊断（必调硬门禁，严禁零论文水报告）**：选哪篇由 AI 大脑根据当场错因自主裁决，但对未中首选场次「必须至少调用 1 篇切题论文进行深入穿透（附论文文件名与原句）」属于硬性验收红线！严禁不调论文只写纯主观口水借口；无论文穿透诊断的失误分析一律视为偷懒、不予验收。
- 哪个维度的判断与实际不符？
- 是信息不足还是判断逻辑有误？
- 是否有赛前未预见的因素（红牌、伤退、天气等）？
- 泊松 λ 值是偏高还是偏低？偏了多少？

**4c. 经验教训提炼（每次复盘必做）**

从本日所有场次（命中 + 未中）中，提炼**可复用的教训**。不是就事论事，而是找到可以指导未来分析的规律：

格式：

```
💡 教训：{一句话概括}
   来源：{联赛} {主队} vs {客队}（{命中/未中}）
   详情：{具体发现}
   行动：{未来遇到类似情况怎么做}
```

**好教训的标准**：

- 可泛化（不只对这一场有用，对同类型比赛都有参考价值）
- 可行动（明确告诉未来分析时该怎么调整）
- 有数据支撑（不是"运气不好"这种无意义的总结）
- **有论文锚点**（文件名 + 一句原文）；没有锚点不得写入 MEMORY.md
- **状态=待验证**：单场只提假设，不写永久禁令；禁止叠例外条款

示例：

```
💡 教训：客胜一端被系统性看轻时，不得只用平赔阈值定生死
   来源：{联赛} {主队} vs {客队}（未中）
   论文：2004_Levitt_NBER_w9422.pdf
   原文：bookmakers ... systematically exploit bettor biases by choosing prices that deviate from the market clearing price
   详情：{当场三端哪一端看轻了；禁止写案例号或门禁名}
   行动：{检查动作}；状态：待验证
```

将有价值的教训整理为待写入内容，步骤 8 验收后统一更新 MEMORY.md 的「关键教训」部分。**不是每天都有新教训**——写不出原文就不写。有则记下来，且必须带论文锚点与「待验证」。同时写入 `MEMORY.md` 的 `## 待验证` 表（一行一条）。

### 步骤 4.6：待验证回检（用后面的球，不改永久规矩）

每次复盘先读 `MEMORY.md` 的 `## 待验证`。今日场次若触发该条检查：

- 按「假设ID＋matchId＋赛前配对版本」记录支持/反对及依据；复核同一条只修原值，不重复加票。无事前触发定义或已知答案后才提出的假设，仅记案例，不充作其验证样本；步骤 8 统一落账
- 禁止因 1 场支持就升级成长期规则
- 样本不足 8 场：维持待验证
- 反对不少于支持且满8场：检查失败原因与同场概率分差，决定暂停或继续观察，不按票数自动改变永久规则
- 支持明显多于反对且满 8 场：仍只标「待滚动检验」，不自动变成门禁

**论文增强回检**：保留当场支持／反对说明，但方法有效性须比较同场同资料时点保存的旧／增强首选和点概率，连同观望比例、累计分差报告（Giacomini、Choe、Wilkens）。无配对记录不赛后补造；观察窗口事先定，未实施正式检验不称显著提升。达到8场只是检查起点，不证明改善；Macri允许核实重大状态变化时快速调整，不由单场Top6未中推倒模型。按Aiyer区分过程与赛果，答案已知就注明已知；按Levitt等回检庄家假设和热度依据，不因无真实注额就否定整个推演，也不以命中倒证庄家账本。

**市场基准与修正增益**：在相同比赛、相同赛前截至的冻结资料上，对比市场基准与最终修正的首选命中、概率评分及覆盖率；市场基准排序只作对照，不替代读盘首选。逐场记录修正改变了哪端、用了何种新增证据，区分修正改善、恶化或未改变判断。市场/泊松/综合概率分源，不用泊松改善代替优于市场；没有合法综合概率就只评价方向并报缺失。稳健性检查按赛前留存的全部变体评价，不赛后选择有利变体。按事先定义的范围和窗口检验哪些修正带来持续增益；观察不到优势则保留市场基准并暂停该候选修正，不能由单场失手强制回归市场，正式规则变更仍需授权。

**迭代的实际闭环（复用现有待验证表与每日记录）**：
- 每个候选改进先留一条：假设ID、论文锚点、错因、唯一主要改动、旧/新方法版本、适用范围、事先确定的评价窗口与成功/失败依据。单场已知答案只能提出假设，不能进入其验证样本；不因当天领先临时延长或缩短窗口。
- 后续比赛在同一资料截至、未见结果时分别冻结旧/新首选、次选、分源概率或缺失、观望及差异理由；不将一法结论或目标答案提示给另一法。没有配对就标缺，不赛后补造；参数用过去拟合，后续窗口评价。
- 到窗口比较同场首选命中、三项布莱尔/可选对数损失、概率校准及出手覆盖率（有效推荐数/事先定义的符合范围场数）；观望、缺概率、抓取失败、污染及排除原因同时报告。概率评分只在双方都有合法冻结概率的配对集合比较并报数量；分母变化不能冒充改善，交易收益另记实际可成交价和费用，不替代预测正确率。
- 状态按「待验证→保留观察/建议采用/暂停撤回」更新同一条目；结果反对时查原因，没优势或新增复杂性不值得时撤回候选。自动记录和生成建议，不自动覆写正式规则；正式升级需明确授权、版本与可回退依据。未做正式统计检验仅称观察改善，既有8场只是检查起点。

没有触发则写「今日无待验证回检」。

### 步骤 4.5：反事实分析

对每场推荐做“如果采用赛前另一种解释会怎样”的回顾，帮助识别偏差。只使用已存同一时点、同一玩法的可成交报价与正确结算；缺报价、费用或注额则只讨论方向，不填盈利数字。不得把独赢倍率套到让球收益，也不能凭赛果倒证真实资金流或机构意图：

- **推荐主胜但实际客胜/平局**：如果反着买（客胜/平局），赔率是多少？盈利几何？
- **推荐大球但实际小球**：反向操作收益如何？
- **比分未中**：实际比分是否不在泊松 Top 6 中？λ 值是否明显偏高或偏低？

输出格式：

```
🔄 反事实分析：
- {比赛1}：推荐{推荐} → 实际{结果}。反向操作赔率 {X.XX}，{反思}
- {比赛2}：...
```

关注的模式：

- 如果连续多天反着买都能中 → 存在系统性方向偏差，需要在策略调优中记录
- 如果实际比分持续不在泊松 Top 6 内 → λ 值估算可能系统性偏高或偏低

### 步骤 5：计算统计

**当日统计**：

- 推荐场次数（含赢半/输半各计 1 场）
- 命中场次数（全赢计 1，赢半计 0.5）
- 走水场次数（不计入命中率）
- 命中率 = (全赢 + 赢半×0.5) / (总推荐 - 走水)（与步骤 3 公式一致）
- 大小球盘口轻量锚定（OU Anchor）效果统计（仅统计有记录的场次；旧摘要缺字段的不计入）：
  - 启用锚定场次：N 场；未启用：M 场
  - **大小球严格命中率对比（首选）**：启用组 {XX%} vs 未启用组 {XX%}
  - **λtot 误差对比**（可选，若你在逐场里已计算）：启用组平均 |(实际总进球)-(锚定后 λtot)| vs 未启用组平均 |(实际总进球)-(原 λtot)|

**计算累计统计的待写入结果（本步不写 MEMORY.md）**：

先读取 MEMORY.md 中的现有统计：

```
memory_get MEMORY.md
```

按既有原日贡献计算差量（与 MEMORY.md 结构一致），步骤 8 是唯一落账点。首次记录才增加；重复运行无变化则差量为零；更正用「新贡献－旧贡献」。逐项以 matchId＋发布版本＋指标去重，候补不混入精选，缺失不进相应评分分母：

- **累计战绩 · 总**：新总数 = 已入账总数－本批旧贡献＋本批新贡献；命中率用修正后分子/分母重算，不因再次复盘重复增加
- **累计战绩 · 各联赛**：按联赛维度累加推荐数、命中数，更新该表（新出现的联赛自动增加一行）；命中率 = 该联赛命中数 / 该联赛推荐数
- **比分预测统计 · 总**：精准命中数、进球数正确数、精准率、泊松模型质量
- **比分预测统计 · 各联赛**：按联赛维度累加精准命中、进球数正确、推荐场次，更新该表（新联赛自动增加一行）；精准率 = 该联赛精准命中 / 该联赛推荐场次
- **各玩法命中率**：按玩法类型累加，玩法为 **胜平负、亚盘、大小球、进球数** 四类（让球推荐计入亚盘）；更新表格中对应行的推荐数、命中数、命中率
- 泊松模型质量：Top 4 命中率、Top 6 命中率、λ 偏差方向
- 串关统计：推荐组合数、命中组合数、按串关类型分（2串1/3串1/比分串/混合串）
- 反事实偏差监测：是否存在连续反向命中趋势

### 步骤 6：策略复盘（当累计数据 >= 20 场时）

当累计推荐达到 20 场以上，额外做一次策略复盘：

- 哪个联赛命中率最高/最低？
- 哪个玩法命中率最高/最低？
- 高信心度推荐的命中率 vs 中信心度的命中率？
- 是否需要调整策略？（如「英冠命中率持续低于 40%，建议降低英冠场次的优先级」）

将策略复盘结论交步骤 8 统一更新 MEMORY.md 的「策略调优记录」，不另行重复写入。

### 步骤 9：推送

交互会话向主人回复已验收报告；定时会话只返回最终报告，由调度器投递，禁止再用 messaging 重复发送。有真实回执才标已投递；仅返回报告记待投递确认。执行失败时定时会话以 `[CRON_FAILURE]` 单独作为第一行，后接具体失败、已保存位置及待办，不能只说启动成功。

## 特殊场景

### 比赛未全部完场

如果部分推荐比赛尚未完场（如凌晨场次）：

- 先复盘已完场的
- 标记未完场的为「待复盘」，写入当日 memory：若该日 memory 中**已存在** `### 待复盘` 子块 → **替换**该子块内容为本次待复盘表格；若不存在 → 在 `## 赛后复盘` 下追加该子块。格式如下：

```
### 待复盘

| 比赛 | 比赛ID | 推荐 | 原因 |
| ---- | ------ | ---- | ---- |
| {主队} vs {客队} | {matchId} | {推荐内容} | 比赛未完场 |
```

- **补追机制**：每次先查前 3 天待办，再沿上一轮留存引用追踪更早的延期场次。超过 3 天仍未完场不等于取消：保留「延期/待赛果」及下次核查条件；只有来源明确确认取消才记取消。补完同步销掉原日该场待办，已计贡献只替换不累加。

### 比赛取消/推迟

- 标记为「取消」或「延期」
- 不计入命中率统计

### 首次复盘（无历史数据）

- 正常计算当日统计
- 累计统计 = 当日统计
- 跳过策略复盘（数据不足）

## 输出

复盘报告与实际处理/方法证据/投递状态；列出已更新的文件、计入统计的差量及待办。仅写本地不能称已推送，子任务返回不能自动称已完成，永久缺失指标不计未中。
