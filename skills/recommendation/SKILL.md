# 推荐输出（recommendation）

逐场推送 deep-analysis 的分析结果，最后发送汇总消息（默认附带胜负平 2 串 1 组合建议）。

**核心原则**：主人主玩「胜负平（1X2）」，以「胜负平 2 串 1」为主要组合方式。推荐输出以工整标准 7 列表格（首选/次选、让球、点概率、诱盘破译、真实交易链接）为主，汇总默认附带高概率与高确定性的 2 串 1 组合建议。同时保留真实交付链接（Polymarket）。独立泊松和比分只作分析依据，不默认推荐国内让球对冲。

## 输入

**交易交付核验（权威对齐官方 Polymarket `https://docs.polymarket.com/llms.txt` 规范）**：
1. **官方标准发现流（Discover Markets via API，严禁客户端拼词猜 Slug）**：
   - 严禁模糊盲搜 `public-search`（防范天气市场冲刷与老完场赛事占位）；调用 Gamma API 权威字典（`GET https://gamma-api.polymarket.com/events?series_id={id}&closed=false&limit=100`，如欧冠 UCL 10204、英超 EPL 10188）分类精准锁定；单事件请求严格锁定单 `slug`（`GET /events?slug={slug}`），杜绝长报文溢出；
   - 在返回事件中比对对阵双方与开球日期，核验活性（`active: true` 且 `closed: false`）及 `teams[].ordering` 主客顺序，提取官方原生 `event.slug` 与 `gameId`；
2. **可执行流动性与挂单核验（CLOB API & Derivates）**：
   - 真实买卖报价：调用 CLOB API `GET https://clob.polymarket.com/book?token_id={tokenId}` 核验 Yes 合约买卖深度与实际成交价；Gamma 展示价仅作参考，不当买入保证；
   - 衍生全系标的：通过 `gameId` 调用 `GET https://gamma-api.polymarket.com/events/keyset?game_id={gameId}` 展开 Exact Score（波胆比分）与 Halftime（半场盘）；
3. **交付标准与门禁**：
   - 7 列表最后一格格式严格锁定为：`[{主队 vs 客队}](https://polymarket.com/event/{slug})` 或带报价版 `[{主队 vs 客队}（{价}¢/{倍}倍）](https://polymarket.com/event/{slug})`；
   - 核心主流联赛（英冠、欧冠、五大联赛等）Polymarket 必定开盘，必须通过主客英文名及别名深度检索定位真实标的，严禁使用任何借口打标未开盘；若偶遇极冷门边缘次级赛事且官方经 Gamma/CLOB 确未收录，方可如实标注『官方未开盘』并保留空链接，绝不允许编造任何免责套话或格式假声明。链接规范已全面内化，严禁猜测拼接。

来自 deep-analysis 的每场比赛综合评估结果。**执行 recommendation 时**，以收齐的 announce 所包含的**综合评估与 memory 摘要**为输入，**无需**再从 memory 读取 `## 深度分析`。

**资料闸门：亚盘/欧指时序空、只有体彩静态赔没有国际机构时序 → 验收绝对不通过，严禁继续十步，严禁对外发布！马上置顶发出严重警报并物理阻断。缺数据绝对禁止静默、绝对禁止跳过或无米之炊硬推。伤停未核实不是验收失败：贴页上原句后继续十步，未核实不得写成全主力。其他来源齐全且真实对得上可以通过。** **按本批实际分析场次数对齐逐场 `matchId`：当期开售全部 N 场（Count(契约卡) ≡ N）都要有开球前实际发布版、首选/次选、胜/平/负点概率（无可靠估计写缺失）、三端裁决的关键反证、赔率报价公司与时间、市场逐家去水聚合口径、战意/伤停核实状态（未核实不得写成全主力），以及与盘赔推荐比分分开的独立泊松 λ/Top 6（未算就标未算）。**发布前核对第 3 列：首选与次选必须是两个不同结果（胜/平/负中的两项）。写成同一项视为单选，验收不通过，退回改次选后再发。深盘热门、体彩关闭基础胜平负（had=None）、口头「无悬念做胆」均不得例外。**记录每场哪些证据已验、哪些未验。**

**流程衔接说明**：

- **编排/多场场景**（赛前全流程、手动多场分析、全量推演）：**单场worker完成10步后先回传待验收报告及证据**，worker不先行对外发布。主会话／编排收齐后验收本批场次，先保存本批全部实际分析摘要与契约卡（执行 Count(契约卡) ≡ N 强断言核销），再交付全量标准 7 列表格。recommendation一次执行全量表格组装（步骤2）→ 胜平负汇总（含文末 2 串 1 组合，步骤3）→ 按步骤5保存待发布版 → 步骤4交付并回填投递状态。
- **单场场景**：单场 worker 完成后主会话收齐 announce，再执行 recommendation（单场推演、汇总、写 memory）。
- 上述任一场景下，**初筛通过 0 场**时无深度分析输入，recommendation 仍须执行（见下）。

**初筛通过 0 场时**：无深度分析输入，recommendation 仍须执行——生成一条汇总消息（今日无候选场次，无推荐），写入 `## 推荐` 并推送给主人，以便 Heartbeat 与流程状态一致。

## 执行步骤

**当深度分析场次为 0 时**（对应窗口初筛通过 0 场）：跳过步骤 1–3，直接生成一条汇总消息「本窗口无候选场次，无推荐」，先写入该窗口 `## 推荐` 再交付（推演 0 场、无串关），然后结束。早盘零候选只结束早盘，不短路晚盘。推送消息可带一句「⏳ 今日体彩销售窗口至：{22:00/23:00}（线上 Polymarket 与线下实体店双轨兼顾）」。**写入的 `## 推荐` 仍按步骤 5 的标准结构**（含 ### 📊 深度推演总表、### 🎯 2 串 1 组合推荐）。总表无数据行。失败空返回的赛程不得走此零场分支。

### 步骤 1：逐场推送分析报告（内容格式规范）

**编排/多场场景下**：单场报告验收后已逐场发布的，不重复发送；未验收或未发布的先完成回传验收，再进入步骤 2（全量汇总）。

**非编排或需本 skill 输出单场时**：分析完一场先验收并按步骤 5 保存该场待发布版本，再按步骤 4 交付，不等全部分析完。主人可以边看边决策。以下为单场报告的内容与格式规范。

**默认交付**：验收后只发七列表（场次/时间、对阵双方、胜负平、让球、胜/平/负点概率（OO-EPC去水）、庄家诱盘破译、Polymarket 真实链接）。第 3 列只放首选/次选且不折行。第 4 列为体彩让球推荐，必须标注官方让球数（【推演源数据】 `sporttery.letBall` 如 `[-1]` 或 `[+1]`，严禁幻觉）与物理三维推演（净胜球）自然解算出的推荐选项（如 `[-1] 让平（次选让负）` 或 `[+1] 让胜`），与胜负平完全自洽闭环。第 5 列只放三个百分比点概率（统一格式如：胜 XX.X% / 平 XX.X% / 负 XX.X%，严禁直接显示 0.xx 小数，直观呈现胜平负概率结构）或缺失说明。单元格须标明实际方法：已执行 OO-EPC 才可按该方法填写；未执行则直写未执行，另列比例法时只标比例法市场参考。禁止借表头把综合判断包装成 OO-EPC。禁止把第 3 列写成「终审人话指令」。禁止把第 5 列写成「真实赛果剧本」。以下长模板仅供明确要求详细报告时使用；完整十步必须执行，未要求过程不自动发送第二条。

扩展分析或明确请求其他玩法时的表述规范（不改变默认七列表）：

- **编号**：来自初筛或当日赛程；主人直接指定比赛 ID/URL 时可能无编号，填「-」即可。
- **分析报价（证据必留）**：亚盘即时盘口与主客水、欧指完整三项及报价时点保存在后台分析证据；不是主人可执行的Polymarket买入价。明确要求展开时可展示，交易报价按输入节另核CLOB。
- 胜平负：保留首选＋次选格式，**首选继承deep-analysis第7—9步完成让球/RLM与三端裁决后的结论**，次选按原交叉依据给出；汇总不退回仅看欧指。现有命中账按原口径，新研究另列首选正确与双选覆盖，不把覆盖当单选准确率。
- 亚盘：「主队让{X}球 主胜」「主队受让{X}球 主胜」；方向不明确时标「⚠️ 观望」
- 大小球：改为 **首选 + 次选** 两档盘口：`首选 大/小 X 球；次选 大/小 Y 球`（盘口：X/Y，预期总进球：λ1+λ2）。次选用于覆盖/风控；方向不明确或与泊松比分重大矛盾时标「⚠️观望」。
- 比分：「比分 X:X」
- **两套比分（deep-analysis 矛盾场次）**：当 deep-analysis 输出了两套比分（整体 Top 3 + 与大小球同方向 Top 3）时，recommendation 的汇总表「比分」列默认填整体 Top 3；同时在该场的「核心矛盾」或「理由」中补一句「本场存在大小球 vs 泊松比分矛盾，另有同方向 Top 3 参考」。

**玩法与统计范围**：默认只推荐 Polymarket 胜平负，亚盘、大小球和比分是分析依据，不自动计为投注推荐。只有主人明确请求并在赛前实际发布的其他玩法，才按对应口径独立评分；标注观望的玩法不计入推荐命中统计。历史多玩法账保留原口径，不重算。首选命中、双选覆盖与独立泊松分别记录，不能互相替代。

**逐场推送**：每场报告由主会话/编排完成回传验收，且本批全部实际分析摘要和契约卡已保存后推送；未验收或本批保存未完成不对外发布。

**消息长度控制**：单条消息如超过 4000 字符，拆分为多条顺序发送（飞书等通讯渠道有长度限制）：

- **逐场分析报告**：本批全部实际分析摘要及契约卡已保存后，默认只发七列表卡片及胜/平/负点概率；若主人明确要求查看过程，再按「先结论后过程」拆条发送（首条末尾「⬇️ 接下文」，续条开头「⬆️ 接上文」）。
- 汇总消息：如超长，按「全量推演推荐表（含文末 2 串 1 组合）」和「风险提示」拆条
- 拆分时在首条末尾标注「⬇️ 接下文」，续条开头标注「⬆️ 接上文」

### 步骤 2：全量 7 列表格交付（当期开售全部 N 场 100% 进表，无一遗漏）

全部场次深度分析完成后，对所有当期开售并进货的 $N$ 场比赛进行**全量 1:1 工整标准 7 列表格汇总交付**。进货 $N$ 场 ≡ 推演 $N$ 场 ≡ 契约卡 $N$ 份 ≡ 交付 $N$ 行，杜绝任何场次裁撤或分表截断！

**全量组装与展示原则**：

- **单一全量表格**：当期开售全部 $N$ 场比赛 100% 呈现在唯一一张工整标准 7 列表格中，严禁分立“核心表”与“次级表”，严禁借口“精选2~3场”在赛前抛弃其余场次！
- **精选概念降维**：“精选”仅指文末的【🎯 精选 2 串 1 组合推荐】（从全量 $N$ 场中挑选出确定性最高的 2 场比赛组成 2 串 1 方案），绝不反向减少推演表格本身的行数；
- **全量覆盖与避险呈现**：若某场比赛存在深水诱盘、高赔真空或分歧矛盾，在第 6 列【庄家诱盘破译】中如实点破做市陷阱并提示避险，绝不弃推。





- **全量 1:1 覆盖纪律**：严格遵循 `MAX_DAILY_ANALYSIS: ALL`，所有当期开售比赛 100% 逐场排队推演进表，严禁借口“精选”人为截断为 2~3 场！
- 主人指定场次时（如「分析 001 和 002」）→ 精准推演指定场次，严禁擅自增减；
- 如果所有场次信心度均偏低 → 7 列表格全部正常呈现，如实于第 6 列提示做市陷阱与避险原因，文末 2 串 1 提示风险。

### 步骤 3：生成全量 7 列表格汇总消息（默认附带文末胜负平 2 串 1 组合）

**7 列表格机械单射组装铁律（Anti-Hallucination & Deterministic Projection）**：
- 推荐汇总中的 7 列表格**严禁编排者在大脑中重新手打**！
