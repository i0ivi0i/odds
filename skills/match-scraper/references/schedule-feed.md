# 赛程 Feed 解析规范（`bf_jc.txt`）

> 机器入口：`https://jc.titan007.com/xml/bf_jc.txt?{timestamp}`
> 唯一落盘工件：`data/{销售日}/meta.md`
> 禁止：把 Feed 本身或任何 `.txt` 中间文件写进 `data/`、仓库或 `tmp_*`。

## 1. 为什么不用 `index.aspx`

`https://jc.titan007.com/index.aspx` 只是人类浏览入口。它是静态骨架页，没有比赛行；抓它只会得到 0 场或空表格，属于假完成。

官方赛程 Feed 是：

```text
https://jc.titan007.com/xml/bf_jc.txt?{timestamp}
```

时间戳用于绕开 CDN 缓存，保证拿到当日最新开售列表。

## 2. Feed 结构

Feed 是 UTF-8 纯文本，以 `$` 分为两段：

```text
联赛字典$比赛记录!比赛记录!...
```

### 2.1 联赛字典（`$` 前）

每条以 `#` 分隔，通常形如：

```text
联赛ID^联赛名^颜色#联赛ID^联赛名^颜色
```

用 `[5]` 的联赛 ID 在这里映射中文联赛名；映射不到时保留 ID 并标记 `unknown_league`。

### 2.2 比赛记录（`$` 后）

每条记录以 `!` 分隔，字段以 `^` 分隔：

| 下标 | 含义 | 示例 | 备注 |
| :---: | :--- | :--- | :--- |
| `[0]` | 比赛 ID（matchId） | `3073801` | 进货与 raw 文件名唯一键 |
| `[1]` | 开球时间 | `2026,9,22,00,45,00` | `Y,M0,D,h,m,s`，**月份 0 基** |
| `[2]` | 联赛/轮次辅助字段 | — | 保留原文，不猜 |
| `[3]` | 状态 | `0` / `1` | 以 Feed 为准，不自行改写 |
| `[4]` | 竞彩编号 | `周四001` | 如无编号，如实留空 |
| `[5]` | 联赛 ID | `123` | 映射联赛字典 |
| `[6]`–`[7]` | 主/客队 ID | — | 仅辅助 |
| `[8]` | 主队中文名 | `格拉茨风暴` | 与 `1x2d.js` 实体核对 |
| `[9]` | 主队英文名 | — | 可空 |
| `[10]` | 客队中文名 | `马赛` | 与 `1x2d.js` 实体核对 |
| `[11]`–`[16]` | 比分/半场 | — | 赛前为空；复盘时读取 |

## 3. 月份 0 基

`[1]` 的月份从 `0` 开始：

```text
2026,9,22,00,45,00
 年  ↑  ↑  ↑  ↑  ↑
     9月 22日 00:45:00
```

即 `9` = 十月。解析时必须 `month = int(parts[1]) + 1`，否则会把 10 月 22 日算成 9 月 22 日。

## 4. 过滤与落盘

1. **销售日过滤**：按解析后的 `YYYY-MM-DD` 等于 `data/{销售日}` 过滤；跨日记录不得误算进当日。
2. **编号过滤**：需要按 `周四` 或指定编号筛选时，以 `[4]` 为准；不要用行号代替编号。
3. **全量保真**：当日开售 N 场就写 N 行；不得“精选”截断。
4. **唯一落盘**：解析结果只写 `data/{销售日}/meta.md`，并追加 `memory/{销售日}.md` 的 `## 赛程抓取（HH:MM）`；Feed 原文读完即弃。
5. **失败处理**：Feed 返回空、HTML 错误页或字段不足 11 个时，如实报错并置顶告警；绝不写 0 场假成功，也不落 `.txt` 兜底。

## 5. `meta.md` 最小字段

每场比赛至少包含：

```text
| 编号 | 开球时间 | 联赛 | 主队 | 客队 | matchId | 状态 |
```

`matchId` 必须来自 `[0]`，并与后续 `raw/{matchId}.json` 的 `match.match_id` 一致。
